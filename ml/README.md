# Юридический ассистент ПСБ

ИИ-ассистент для работы с нормативными документами на основе **RAG (Retrieval-Augmented Generation)**.

Отвечает на вопросы по законодательству РФ, договорам и внутренним регламентам компании: находит подтверждающие положения в базе знаний, формирует ответ со ссылками на конкретные пункты и обоснованно отказывается, если сведений недостаточно.

## Возможности

- Гибридный поиск: семантика (BGE-M3) + лексика (BM25), объединение через RRF
- Ответы со ссылками на документ и пункт, проверяемыми по базе знаний
- Три вида контроля достоверности: ссылки, обоснованность, отказ
- Обработка коротких диалогов: ответ на последнюю реплику с учётом истории
- Устойчивость к инъекциям промпта, спрятанным в документах
- Автоматическая оценка качества поиска: Hit@5, Recall@5, MRR@10

## Архитектура

```
Документы → Чанки → Dense (BGE-M3) ┐
                                   ├→ RRF → бонус за сущности → Top-k
                  → BM25 (стемминг)┘
                                                    ↓
                            LLM → Верификация → Исправление → Ответ
```

1. **Ingestion** — чтение `.txt` из базы знаний, нарезка по границам статей и пунктов с сохранением заголовка документа и метаданных статьи. Для законов блоки крупнее (1600 символов), для документов компании — 1200.
2. **Dense Retrieval** — эмбеддинги `BAAI/bge-m3`, косинусная близость, кэш индекса на диске с фингерпринтом по модели и текстам чанков.
3. **Sparse Retrieval** — `BM25Okapi` с русской токенизацией, нормализацией `ё→е` и префиксным стеммингом (6 символов). Номера статей и договоров сохраняются как есть.
4. **RRF** — Reciprocal Rank Fusion по позициям в обоих рейтингах, `rrf_k=60`, по 30 кандидатов от каждого метода.
5. **Бонус за сущности** — небольшой довесок к RRF-скору за точное упоминание контрагента или номера договора. Граница слова не даёт «Альфа-Трейд» совпасть с «Альфа-Трейдинг».
6. **Generation** — ответ LLM по найденным фрагментам с жёстким системным промптом и четырьмя примерами.
7. **Verification** — проверка ответа и одна попытка исправления, если найдены проблемы.

## Запуск

Все команды выполняются из директории `ml/`.

### Зависимости

```bash
uv sync
```

или

```bash
pip install -r requirements.txt
```

### Данные

В `ml/data/` должны лежать `knowledge-base.zip` и `questions.csv`. Архив распаковывается автоматически в `data/kb_extracted/` при первом запуске.

### Локальный режим

Требуется запущенная [Ollama](https://ollama.com) с моделью генерации:

```bash
ollama pull qwen2.5:7b
python solution.py
```

Эмбеддинги считаются локально через `sentence-transformers` (`BAAI/bge-m3`), при наличии CUDA — на GPU в fp16. Первый запуск строит индекс, дальше он берётся из кэша `data/indexes/`.

### Режим платформы

Если задана переменная `EMB_MODEL`, эмбеддинги запрашиваются через OpenAI-совместимый прокси, а `torch` и `sentence-transformers` не импортируются. Генерация всегда идёт через прокси по `LLM_BASE_URL`.

```bash
export LLM_BASE_URL=... LLM_API_KEY=... LLM_MODEL=... EMB_MODEL=BAAI/bge-m3
python solution.py
```

Результат — `submission.csv` в рабочем каталоге, колонки `id,answer`, UTF-8. Файл перезаписывается после каждого вопроса, поэтому частичный результат сохраняется при таймауте или прерывании.

### Предрасчёт индекса

```bash
python scripts/build_index.py
```

## Контроль достоверности

Ответ проходит три проверки перед отправкой. Если найдены проблемы, выполняется одна попытка исправления с перечислением ошибок; принимается вариант с меньшим числом проблем.

**`citations.py`**
- каждый упомянутый пункт или статья должны буквально присутствовать в переданных фрагментах;
- название документа рядом со ссылкой должно совпадать с документом-владельцем пункта;
- ссылка без названия документа отклоняется;
- неподтверждённые ссылки в скобках вырезаются принудительно.

**`grounding.py`**
- маркеры предположений: «рекомендуется», «возможно», «например», «может касаться», «не предусмотрено»;
- иероглифы и более двух иностранных слов — ответ должен быть на русском.

**`abstention.py`**
- отказ при высокой релевантности найденных фрагментов считается необоснованным и оспаривается.

Дополнительно системный промпт запрещает выполнять инструкции, спрятанные внутри документов, и требует применять исключение из нормы вместо общего правила.

## Evaluation

### Автоматическая оценка поиска

Разметка в `evaluation/labels.json` задаёт для каждого вопроса нужный **документ и пункт**, а не идентификатор чанка — поэтому она не ломается при изменении нарезки.

```bash
python -m evaluation.evaluate_retrieval --failures
python -m evaluation.evaluate_retrieval --compare-stemming --json eval_report.json
```

Параметры:

- `--labels` — путь к разметке
- `--top-k`, `--candidate-k` — глубина оценки
- `--no-stemming` — отключить стемминг BM25
- `--compare-stemming` — сравнить BM25 и Hybrid с стеммингом и без
- `--failures` — список вопросов с `Hit@5 = 0`
- `--json` — выгрузка сводки и результатов по каждому вопросу

Метрики:

- **Hit@5** — доля вопросов, где нужный фрагмент попал в топ-5
- **Recall@5** — доля покрытых требований в топ-5 (для вопросов с несколькими источниками)
- **MRR@10** — обратный ранг первого релевантного фрагмента в топ-10


Стемминг на этом наборе не меняет результат. BM25 ранжирует точнее гибрида, гибрид страхует покрытие на формулировках без лексического совпадения.

### Отладка одного вопроса

```bash
python evaluation/inspect_retrieval.py -q "Какой максимальный срок испытания для главного бухгалтера?"
python evaluation/inspect_retrieval.py            # интерактивный режим
```

Показывает рейтинги Dense, BM25 и Hybrid с позициями, оценками, названиями документов и текстом фрагментов.

Параметры: `-k 10`, `--candidate-k 30`, `--full-text`.

Пример вывода:

```text
HYBRID RANK: 1
DOCUMENT: законы__ТК_ст70_действующая.txt
RRF score: 0.032787
Dense rank: 1
BM25 rank: 1
```

## Известные ограничения

- Реранкер `Qwen3 Reranker 8B` не подключён; используется только RRF.
- Разметка охватывает 18 демо-вопросов, часть требований задана на уровне документа без пункта — метрики по ним завышены.
- Валидатор проверяет существование и принадлежность ссылки, но не семантическую правильность: существующий, но не тот пункт может пройти проверку.
- Локальная модель слабее платформенной `DeepSeek V4.1 Flash`, поэтому локальные ответы хуже по формулировкам при том же поиске.
- Для автоматического сабмита нужен плоский ZIP: `solution.py` и все модули в корне архива. Сборка пока выполняется вручную.(в будущем)
- Веб-интерфейс, `Dockerfile` и `compose.yaml` в работе — обязательны для финальной сдачи.
